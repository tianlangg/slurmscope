# Architecture decisions

## Durable queue in PostgreSQL

The API creates queued run records and returns immediately. A standalone worker
claims those records with a transaction and persists `SUBMITTING` before calling
an executor. This keeps long-running work out of HTTP request lifetimes and
makes the queue inspectable after a restart without adding Redis or a broker.

## One run model, multiple executors

The worker depends on an executor contract for submission, status, cancellation,
and logs. The local process adapter and Slurm CLI adapter normalize their results
into the same lifecycle. That lets the API and frontend treat a run consistently
while keeping backend-specific behavior contained.

## Explicit recovery states

PostgreSQL is durable, but a local child process is not guaranteed to survive a
container or host restart. The local adapter checks process identity and an
atomic completion marker; unrecoverable local work becomes `LOST`. A Slurm run
missing accounting data remains `UNKNOWN`. If Slurm submission may have
succeeded but its job ID was not committed, the worker does not resubmit it
automatically.

## Safe workload interface

The browser selects a server-approved template and supplies numeric allowlisted
parameters. Local execution uses an argv list with `shell=False`. Slurm batch
files contain a trusted template body and validated values. Artifact paths are
generated by the server and log reads are bounded and checked against the
configured artifact root.

## Verification boundaries

Unit and integration tests pass against PostgreSQL in Compose, and the local
six-run flow was exercised with the real worker and benchmark. Slurm CLI behavior
has mocked coverage, but live compatibility still depends on an authorized
cluster, its accounting configuration, and shared artifact storage. The project
does not claim a live Slurm run or a hosted GitHub Actions result until those are
recorded.

The React Router, Vite, and Vitest dependencies were moved to patched major
versions after `npm audit` identified critical and high advisories in the
previous versions. The updated lockfile installs cleanly and `npm audit` reports
zero vulnerabilities. The frontend Docker build uses `npm ci` to install that
lockfile reproducibly.
